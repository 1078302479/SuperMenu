## 我们自己的体验

1. 菜单工作台：左侧功能分区，中间动作开关与顺序，右侧同时预览空白处/文件/文件夹/图片场景。默认只显示常用动作，其余放入 SuperMenu 子菜单。
2. 模板库：内置模板与我的模板分区，显示格式、默认文件名、是否直接显示在主菜单；导入模板后可立即试建。
3. 目录与应用：同一位置配置移动/复制目标；检测 App 安装状态，文件与目录的打开规则独立。
4. 工具箱：图片转换、校验、二维码通过轻量面板完成；批量任务显示进度与失败项。
5. 权限与诊断：分别展示 Finder 扩展、文件访问、自动化权限和外部工具状态；只在需要时请求权限。
6. 危险操作：永久删除与解散文件夹独立确认面板，列出将处理的对象，默认不进入主菜单。

## 技术方案与约束

建议 Swift + SwiftUI 主应用，AppKit 承接原生菜单/窗口/共享面板。第一阶段验证 Finder Sync Extension 接入，主程序与扩展以 App Group 共享配置；文件任务放在独立执行层，扩展只生成菜单与派发动作。文字翻译/二维码使用 macOS Services，不能假设 Finder 扩展覆盖所有应用的文字右键菜单。

[Apple 菜单接口](https://developer.apple.com/documentation/findersync/fifindersyncprotocol/menu(for:)?language=objc)允许按所选对象与菜单类型生成菜单。[Apple Finder Sync 指南](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Finder.html)明确其原始用途是同步服务，且不是通用 Finder UI 修改工具。因此 Finder Sync 是待验证路线，系统版本兼容性、通用工具使用边界与商店审核都不能预先承诺。P0 同时评估 Services/Quick Actions 降级入口，并形成采用或调整的结论。

权限分为沙盒目录访问、系统隐私控制、自动化授权三类；“完全磁盘访问”不等于沙盒逃逸，也不保证受保护目录可写。优先以用户选择目录、持久访问书签实现最小授权。第三方应用控制仅在实际使用时申请。独立分发 Developer ID 签名/公证作为首发候选，App Store 另做验证。

建议模块：MenuCore（规则、上下文与顺序）、TemplateStore、FileOperations（复制/移动/冲突/恢复）、AppLauncher、ImageTools、TextServices、IntegrationAdapters、PermissionDiagnostics。配置使用版本化 Codable；第一版无需数据库。耗时操作用任务队列，结果只留必要本地日志；菜单路径不读文件内容、不联网。

## Finder 实际菜单展示核对（2026-11-09）

通过 Finder 在本项目目录分别右击 README.md、design 文件夹、列表空白处，并展开“新建文件”二级菜单。只查看菜单，未执行功能命令。以下反映本机当前配置，不代表软件出厂默认。

- 主菜单：系统动作在前，超级右键动作直接插入其后，并没有强制统一放入品牌子菜单。每个动作可带图标；新建、移动、复制、图标和校验使用二级菜单。当前启用项目较多，菜单超出窗口可视高度，存在浏览成本。
- 新建二级菜单：首项为“自定义创建新文件”，后接启用的 TXT、RTF、XML、Word、Excel、PPT、WPS 模板，各自显示格式图标。未看到未启用的 Pages 等格式。
- 文件场景：出现文件校验、桌面快捷方式、名称、剪切、路径、删除、权限、选中文件隐藏、扩展名、乱码修复和按所选文件命名的 ZIP/7z 入口。
- 文件夹场景：额外出现解散文件夹、添加到常用目录、进入终端、扫描磁盘；本次未见文件校验入口。
- 空白场景：出现新建、常用目录、截图、当前路径、添加到常用目录、全体隐藏/取消隐藏、进入终端、扫描磁盘；未见移动/复制所选文件、彻底删除等对象操作。
- 图标/勾选/蓝色选中态/右向子菜单箭头均遵循系统菜单外观。菜单位置、高度和滚动由系统与屏幕空间决定，不应用网页模拟尺寸作为原生规格。

设计调整：保留“常用动作直接展示”和“按类别收纳”两种配置。预览增加普通文件场景；文件夹不显示文件校验。我们的默认方案应缩短首层菜单，把低频与危险动作收纳，但不能把竞品当前菜单误描述为全部折叠。上下文显示规则独立于开关；当前文件夹作为新建/终端目标，选中项目作为移动/校验目标，两类目标不能混淆。

未验证：图片、多选、剪切后的粘贴状态、云目录、外接盘、合并菜单开关改变后的层级及各命令效果。仍需后续用测试文件专项验证。
