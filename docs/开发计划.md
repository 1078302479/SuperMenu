# SuperMenu 开发计划

规划日期：2026-11-09。以用户最新确认方向和现有交互稿为基线。本文是后续开发执行基线；`产品规划.md` 中历次设计记录仅作为过程参考。

## 目标与当前状态

目标：开发 macOS 原生右键工具，覆盖已记录的 F01–F25 功能，尽量保留超级右键的操作顺序、菜单分组、彩色图标和设置方式，同时使用自己的品牌、应用图标和浅色外观。

当前已完成：网页与本地 2.5.0 界面的功能核对，Finder 文件/文件夹/空白处菜单观察，七页网页设计稿、82 个本地图标参考资源、独立右键主题应用图标。

当前未完成：原生工程、Finder 扩展、真实文件操作、配置持久化、第三方接口适配、签名分发。网页中的按钮、权限状态和任务提示不能视为功能完成。最近的底部裁切修复尚未完成浏览器画面复核，原生实现必须实测小窗口布局。

范围：一期不做账号体系、云同步、付费订阅、独立完整截图编辑器或完整压缩引擎。保留 iShot/FastZip/DiskMap 等外部联动需求。macOS 13+ 和双架构为暂定目标，技术验证后按实测条件确认。

## 产品界面基线

七个入口：通用设置、新建文件、发送文件到、常用目录、文件（夹）图标、工具箱、权限与诊断。使用浅色设置窗口、紧凑表格和彩色格式/功能图标；左上角保留自己的右键标识。

工具箱底部始终可见：新建进入 App、删除、申请其他功能、重置；显示图标与三类合并选项及帮助按钮。默认显示图标，合并选项默认关闭。长列表仅在表格内部滚动。

表格支持名称编辑、顺序调整、启用开关；只有自定义入口可删除。原生右键菜单遵循 macOS 外观，不能以网页绘制的选中态、位置、高度作为系统菜单规格。

## 交付节奏

按一名 macOS 开发者持续投入估算：总计约 8–12 周。它是工作量预估，不是已承诺的日历交付日期。每阶段交付可安装测试包、功能状态清单和遗留问题；P0 完成后收紧时间估算。首次可用目标为第 2–3 周，核心版本目标为第 4–5 周。

| 阶段 | 工作量 | 交付内容 | 进入下一阶段的条件 |
|---|---|---|---|
| P0 系统接入验证 | 3–5 工作日 | 可运行主应用、最小 Finder 扩展、目录授权、真实新建/路径/终端样例；接口可行性表 | 至少在本机验证文件/文件夹/空白处/多选；扩展、授权和配置通信链路成立；无法验证的环境明确标记 |
| P1 原生骨架与模板 | 7–10 工作日 | 七页原生设置框架、持久配置、模板管理、常用目录、首次安装引导；首个内部测试包 | 退出重启后配置保留；有效模板可创建并打开；长表格不挤掉底部；设置与菜单一致 |
| P2 文件操作核心 | 7–10 工作日 | 复制、移动、剪切/粘贴、冲突处理、名称与路径、应用打开、规则与合并菜单 | 跨卷/取消/冲突/磁盘不足不误删源文件；特殊文件名正确；基础工具可连续日常使用 |
| P3 完整工具箱 | 10–15 工作日 | 图标管理、隐藏与扩展名、校验、图片与图标集、替身/共享、文字服务、系统工具 | 批量任务可取消、失败逐项提示；图片保留源文件；风险操作确认；每个动作有真实结果 |
| P4 特殊场景与联动 | 5–10 工作日 | 云目录增强、外接盘恢复、乱码修复、iShot/FastZip/DiskMap 适配 | 依赖可检测、错误可解释；已确认接口真实调用，未打通项不得标为完成 |
| RC 验收与交付 | 5–10 工作日 | 安装包、签名公证、升级迁移、诊断、兼容回归、使用说明 | 发布阻断项清零；干净机器完成安装到首次使用；关键测试矩阵有证据 |

总计 37–60 工作日，按约 8–12 周安排，具体取决于系统接入和第三方接口。没有 Intel 实机或第二个系统环境时，只能报告构建结果和未验证范围，不以“Universal 已构建”替代双架构实测。

## 第一周：先验证决定项目成败的链路

| 顺序 | 任务 | 输出 |
|---|---|---|
| 第 1 日 | 检查 Xcode/SDK、签名能力和本机系统；创建主应用与扩展工程，统一 Bundle ID 与配置模型 | 工程可编译，应用/扩展各自启动；记录开发环境 |
| 第 2 日 | Finder 中获取当前目录和所选对象；验证文件、文件夹、空白、多选场景 | 菜单按上下文出现；不在无效上下文使用过期选择 |
| 第 3 日 | 从右键发起真实 TXT 新建、复制路径、打开终端；配置从主 App 传到菜单 | “设置 → 菜单 → 文件结果”第一条闭环 |
| 第 4 日 | 验证授权撤销、应用退出、Finder 重启、外接盘接入；探索云目录限制 | 权限状态与恢复路径；兼容性表 |
| 第 5 日 | 探查云目录手势和第三方公开接口；整理采用/调整方案，出首份测试包 | 冻结集成路线，标出每个能力的已验证/待验证/阻塞状态 |

第一周的接口探查用于提前发现风险，不要求同时完成全部联动。若 Finder 集成路线不能满足目标，应先调整方案和排期，不能用网页原型代替原生能力演示。

## 原生实现建议

采用 Swift 主工程，设置外壳使用 SwiftUI；对表格行编辑、拖拽排序和窗口尺寸要求较高的区域优先评估 AppKit NSTableView，并在 P0 后确定组合方式。Finder 菜单使用原生 NSMenu；长任务在独立执行层处理，避免菜单回调中扫描磁盘、读取大文件或联网。

建议划分：

| 模块 | 职责 |
|---|---|
| SuperMenuApp | 七页设置、首次使用引导、菜单栏入口、任务结果窗口 |
| FinderExtension | 取得上下文、生成菜单、派发动作 |
| MenuCore | 动作 ID、启用状态、名称、排序、对象类型规则、三类合并设置 |
| ConfigurationStore | 版本化配置、迁移、模板索引、目录书签、主应用与扩展同步 |
| FileOperations | 复制/移动/剪切、冲突策略、取消、结果清单与故障恢复 |
| TemplateStore | 有效模板导入、创建、命名、排序和打开 |
| ToolServices | 校验、图片、图标、二维码、文件元数据操作 |
| Integrations | 终端/编辑器、系统共享与第三方应用适配 |
| Diagnostics | 权限状态、失效目录、扩展故障与最小诊断记录 |

进程间派发机制、App Group 能力和签名在 P0 用真实工程验证后确定。首版不引入数据库。用户设置必须按稳定动作 ID 绑定，不能因改了菜单名称就丢失图标、类型规则或配置。

## 需要提前解决的依赖

1. Finder 接入与云目录：P0 验证，不预先假定同一接口可覆盖所有目录和手势。Services/Quick Actions 作为备用入口，备用方案不能算作已经完成同等右键体验。
2. 文件权限：区分目录授权、自动化、系统隐私权限；不将完全磁盘访问当作所有文件可写的保证。退出、撤销、拔盘等情况能重新定位或重新授权。
3. 联动接口：必须逐个确认公开接口、输入与返回行为；没有可用接口时记录阻塞和替代体验，仍保留原始需求，不悄悄缩减全功能范围。
4. 素材：本地图标继续作为视觉对齐基线；原生实现优先从系统/已安装 App 读取可用的类型图标，其他资源逐项记录来源及发布使用方式。有效文档模板自行准备并验证。
5. 分发：先交付独立测试包；签名、公证与干净机器安装在早期就做一次，正式发布时再回归。商店版本单独评估，避免审核不确定性拖住首次可用版本。

## 验证方式与发布门槛

每个功能都需要完成“界面设置 → Finder/服务入口 → 实际结果 → 失败恢复”，不能仅凭入口存在打勾。

- 自动检查集中于文件复制/移动的故障行为、冲突策略、菜单规则、配置迁移、校验标准向量和图片输出；不为静态布局堆实现镜像测试。
- 真实 Finder 流程覆盖文件、文件夹、空白、多选、图片和剪切后的粘贴；与本机原版同场景逐项对照。
- 位置覆盖本地 APFS、外接 APFS/exFAT、只读卷、云文件的已下载/占位状态；网络卷单列为待验证能力。
- 故障覆盖重名、磁盘不足、复制中断、目标拔出、权限撤销、源文件变化、应用退出与 Finder 重启。
- 界面在最小支持窗口、正常窗口及不同缩放下实测；工具箱底部、确认按钮和错误提示不得被裁切。
- 菜单缓存生成 p95 < 100ms 作为目标；空闲无持续磁盘扫描，大任务不阻塞菜单。测量结果记录环境与样本。

发布阻断项：任何可能导致源文件意外丢失的缺陷、未经确认永久删除、错误目标路径、权限失败被误报成功、设置与菜单状态不一致、必需按钮不可达。其他问题按影响等级记录，可接受的兼容范围须在说明中写清。

## 执行与汇报

每个任务按“未开始 / 开发中 / 已实现 / 待真机验收 / 已验收 / 阻塞”更新，并附测试包版本或证据路径。每阶段汇报已完成结果、未验证环境、阻塞原因和下一批任务。资源缺失可继续独立工作，不以一次运行失败就终止整个阶段。

首个里程碑是 P0，在 Finder 中打通新建 TXT、复制路径和终端打开。当前结果见下方进度记录。

## 0.1.0 开发预览进度

本机已用 Command Line Tools 构建 arm64 应用和嵌入式 Finder 扩展，最低部署版本暂为 macOS 13。使用临时签名时系统拒绝写入 App Group，本地开发包改用构建目录内的共享空间，正式签名版保留 App Group 路线。

已通过原生选择器授权隔离目录，确认主应用保存配置，Finder 实际显示新建 TXT、拷贝路径和在终端打开。同名 TXT 不覆盖、目录边界判断和无授权目录拒绝已通过单独验证。首次从 Finder 点新建没有生成文件，已改用独立的菜单回调，在触发时从 Finder 读取上下文，待复测。其他系统版本、外接盘和云目录待实测。

后台集成测试已使用两个独立的沙盒进程验证 macOS URL 投递、过期与重复请求拒绝、同名 TXT 自动编号与内容保留。测试调用与 Finder 扩展共用的投递代码，接收端为无窗口测试程序。真实 Finder 菜单回调与主应用授权执行仍需联测。

P1 模板功能已实现 TXT、Markdown、RTF、XML，含独立开关和 Finder「新建文件」子菜单。同名文件自动编号。后台测试通过旧设置兼容、格式解析、同名保护和模板请求投递。模板导入、办公文档、其余设置页和 Finder 子菜单实测继续推进。
